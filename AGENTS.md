# Grafik_Project — автоматизация построения графиков СМР из смет

Это текущее состояние знаний и решений по проекту. История событий по датам — Codex-mem.md (только дополняется). Точка входа в начале каждой сессии — HANDOFF.md. Общий фон и первоначальные рассуждения — docs/project_overview.md.

## Цель проекта
Автоматизировать построение календарного графика строительно-монтажных работ (диаграммы Ганта) на основе объёмов работ из локальных смет, с расчётом длительностей через нормы выработки, зависимости, календарь и ресурсы. Результат выгружается в формат MS Project (или аналогичный) для просмотра и редактирования. В перспективе — накопление типовых графиков как заготовок для новых проектов.

## Заказчик и роли
Заказчик — Николай, руководитель, бизнес-заказчик внутри крупной компании, не программист. Работа ведётся полностью внутри Cowork, без отдельного терминала Codex (проект ECID использует другую модель и не связан с этим проектом). Codex в этой работе выступает как супервизор-инженер, разработчик, тестировщик и дизайнер одновременно и обязан критически проверять каждое решение, а не соглашаться автоматически.

## Формат исходных данных
Локальные сметы — Гранд-Смета (основной источник), изредка Смета.ру. Все сметы делаются методом ГЭСН, ресурсным методом (подтверждено заказчиком) — детальная разбивка по труду, машинам и материалам на уровне каждой позиции. .gsfx — нативный формат Гранд-Сметы, вероятно лучше Excel-экспорта; сметный отдел сдаёт .gsfx как основной формат, Excel — по запросу.

## Архитектурные решения (действующие)
1. Система сама считает график по алгоритму (объём / норма выработки, зависимости, календарь, ресурсы), не полагается на встроенный импорт смет в MS Project — он работает плохо и путает позиции. Выгрузка результата — это скрипт, генерирующий файл в формате MS Project XML (MSPDI), а не плагин/надстройка внутри самого MS Project (обсуждено и подтверждено 16.09.2026: скрипт проще, не зависит от версии MS Project, переносится на другой инструмент планирования без переписывания под чужой API).
2. Последовательность работ внутри раздела/подобъекта строится полуавтоматически по иерархии сметы там, где для вида работ есть технологическая карта (ТТК); реальный источник последовательности — именно ТТК, не порядок строк в смете (гипотеза "порядок = технологический порядок" опровергнута заказчиком на реальных сметах). Где ТТК нет — ручной ввод инженером ПТО, не блокирует MVP. Нужна инвентаризация от заказчика, для каких видов работ ТТК уже есть. Связи между разными подобъектами инженер расставляет вручную.
3. Консолидация позиций сметы (когда одна физическая работа разбита на несколько строк из-за формулировок вроде "на каждый следующий проход") — по коду расценки (шифр ГЭСН/ФЕР), не по тексту наименования. Решающий признак объединения — явная текстовая ссылка добавочной расценки "к норме XX-XX-XXX-01" на базовую (совпадения одного префикса шифра недостаточно). Сопоставлять нужно с ближайшей предыдущей позицией внутри той же подгруппы сметы, а не глобальным поиском по коду — одна и та же добавочная расценка может ссылаться на несколько базовых кодов и повторяться в разных подгруппах файла.
4. Определение ведущего ресурса для расчёта длительности позиции: сравниваются суммарные чел-ч труда (ОТ/ЗТ) и суммарные маш-ч машин (ЭМ) внутри позиции целиком, не берётся максимум по отдельной строке. Труд ≥ машинного времени → ведущий ресурс труд (механизация вспомогательная). Иначе — машина с максимумом маш-ч на единицу измерения среди машинных ресурсов расценки (тай-брейк для случая "несколько машин без доминирующего труда"). Пограничный случай ГЭСН01-02-027-02 (планировка площадей, бульдозер 0.35 маш-ч против автогрейдера 0.22, отрыв всего 1.6 раза) до сих пор помечен "на проверку" — ждёт сверки заказчиком в Гранд-Смете. ОГОВОРКА: правило "максимум маш-ч" системно не проверялось на не-земляном сборнике (бетон, металл, отделка) с преобладанием ручного труда при нескольких мелких машинах — на всех проверенных образцах такие случаи пока не встречались.
5. MVP считает график только по чистым базовым сметам, составленным на старте проекта, без истории допсоглашений. Пометки "ИСКЛЮЧИТЬ/ВКЛЮЧИТЬ/ОТКОРРЕКТИРОВАТЬ" не разрешаются автоматически (даже заказчик не может дать универсальное правило) — помечаются для ручной проверки инженером ПТО. Актуализация уже существующего графика в ходе стройки — отдельный сценарий за периметром MVP.
6. Позиции-материалы (код ФССЦ, только количество×цена, без граф труда/машин) консолидируются как атрибут (стоимость/ресурс) предыдущей рабочей позиции, не становятся отдельными задачами графика.
7. Известное ограничение: заголовки технологических подгрупп внутри раздела сметы — произвольный текст без фиксированной глубины вложенности. Двухуровневая модель "подгруппа 1 / подгруппа 2" иногда путает уровни. Не блокирует MVP, но группировку задач графика по технологическим зонам нужно будет доработать, вероятно через стиль ячейки (жирный шрифт/отступ), а не только через контент.
8. Приоритет источников состава звена (решено 17.09.2026, по предложению заказчика): основной источник — ФРСН (актуальная официальная база от Минстроя, 2024 год, ближе технологически к современному ГЭСН). ЕНиР (архивный документ-предок ФРСН, 1986 год) используется только точечно, как запасной источник для случаев, где у ФРСН нет кандидата или явно неверный кандидат — обязательно с пометкой источника в результате (пример: код ГЭСНм39-01-002-19, кандидат заменён на ЕНиР Е27-63 в prototypes/results/2026-09-17_gesn_frsn_candidates_v2.xlsx). Смешивать источники без явной пометки нельзя — это ломает прослеживаемость решения при последующей проверке (важно для исполнительной документации). Родство ЕНиР и ФРСН (общее происхождение норм) не означает, что данные ЕНиР можно считать современными без разбора — устаревшая техника и организация труда 1980-х могут давать другой состав звена, чем сегодня.
9. Поправочный коэффициент на фактическую производительность труда (решено 17.09.2026, по предложению заказчика): нормативная трудоёмкость (ГЭСН/ФРСН/ЕНиР — любая из них) — это плановая величина по методике своего времени, не то, что реально показывает бригада конкретной компании на конкретном объекте. Планирование должно опираться на опыт и статистику компании, а не только на норму. Решение: вводится отдельный поправочный коэффициент, полученный из факта по завершённым объектам заказчика, который применяется поверх нормативного состава звена и трудоёмкости при расчёте длительности (фаза 6). Коэффициент — это надстройка над нормой, а не замена выбора источника (пункт 8 выше): подмена состава звена в поисках более удобной цифры недопустима, а коэффициент — прозрачная и объяснимая поправка. Требует накопления статистики по мере появления факта, не блокирует MVP на текущих объектах без истории (см. открытый вопрос 9 ниже и фаза 6, новый шаг 5 в дорожной карте).

## Состав звена и источник норм труда
ГЭСН не содержит состав звена (профессии, разряды, количество людей) — только суммарные чел-ч и маш-ч. Путь через ЕНиР (архивный документ 1986 года) закрыт — явной ссылки ГЭСН → ЕНиР в изданных сборниках не найдено, официальной публичной привязки нет.

Действующий источник — сборники ФРСН ("Сборники нормативов затрат труда работников в строительстве", официальное название на портале ФГИС ЦС — "Нормы труда", шифр позиции Н-XX-YY-ZZZ-NN-MM). Это действующий, официально изданный, регулярно актуализируемый документ. В отличие от ГЭСН, ФРСН содержит таблицу "Состав звена рабочих" (Код/Профессия/Кол-во) по каждой норме, плюс отдельно НТ рабочих чел-ч и НТ машинистов чел-ч. Все 71 PDF-сборник сконвертированы в markdown и лежат в docs/ФРСН на диске заказчика.

Ключевые ограничения метода сопоставления:
- Номер сборника ФРСН НЕ совпадает по смыслу с номером сборника ГЭСН (проверено на 7 парах вручную, ни разу не совпало; слово "ГЭСН" не встречается ни в одном из 71 файла ФРСН). Сопоставлять коды можно только по смыслу описания (наименование, измеритель, параметры вроде диаметра или материала), не по номеру сборника или коду.
- Числовое совпадение чел-ч НЕЛЬЗЯ использовать как критерий подтверждения пары. Пример: ГЭСН22-03-007-02 "Установка задвижек... диаметром 100 мм" (2.03 чел-ч) по смыслу и диаметру ближе всего к Н-19-02-005-03-01 "Установка стальных задвижек диаметром до 100 мм" (1.4 чел-ч) — тема и диаметр совпадают, чел-ч расходятся.
- Гипотеза (не проверена): коды семейства ГЭСНм (монтаж оборудования) соответствуют сборникам ФРСН из диапазона 49-72 (по темам — вторая половина списка ФРСН это в основном монтаж оборудования). Использовать как один из сигналов ранжирования кандидатов, не как жёсткий фильтр.

РЕШЕНО (2026-09-16): полный список кодов ГЭСН по всем доступным объектам заказчика — prototypes/results/2026-09-16_gesn_codes_full_list.xlsx, 157 уникальных кодов из 23 сборников (109 обычных ГЭСН + 48 ГЭСНм). Прежние цифры 135 и 140 учитывали только один объект ("объект 004", 15 файлов gsfx) — при добавлении объекта Сокур (excel, +15 новых кодов) и Резервуарного парка (excel, +7 новых кодов) итог вырос до 157. Расхождение 135 vs 140 внутри одного объекта 004 не имеет значения дальше — это устаревший промежуточный подсчёт, актуальна только цифра 157.

## Открытые вопросы
1. ЗАКРЫТО (2026-09-16): полный список кодов ГЭСН — 157 из 23 сборников, см. "Состав звена и источник норм труда" выше и файл prototypes/results/2026-09-16_gesn_codes_full_list.xlsx. НОВЫЙ ОТКРЫТЫЙ ВОПРОС взамен: у объекта "004" (gsfx, 135 кодов) и объекта Сокур (excel, 59 кодов) пересеклось только 44 кода из 135 — почему такое маленькое пересечение для, предположительно, смет одного и того же типа работ, не проверено. Возможно, это два разных объекта заказчика, а не два экспорта одного — стоит уточнить у заказчика, не блокирует шаг 2.
2. Гипотеза "ГЭСНм → ФРСН 49-72" правдоподобна по темам, но не проверена ни на одном конкретном коде.
3. Тай-брейк "максимум маш-ч" систематически не проверен на не-земляном сборнике (бетон, металл, отделка) с преобладанием ручного труда при нескольких мелких машинах.
4. Пограничный случай ГЭСН01-02-027-02 (отрыв маш-ч всего 1.6 раза) ждёт сверки заказчиком в Гранд-Смете — не блокирует MVP, единственная такая позиция из 226 в проверенном образце.
5. Нужна инвентаризация от заказчика — для каких видов работ уже есть библиотека ТТК (источник технологической последовательности), для каких нет.
6. Программный доступ к базе норм Гранд-Сметы не исследован — нужен только если когда-нибудь придётся считать по сметам без ресурсной детализации, сейчас не блокирует MVP.
7. Календарь работы для расчёта длительности (5/2, 6/1, вахтовый, праздники) — не обсуждался с заказчиком, блокирует фазу 6, шаг 1.
8. Может ли одна бригада специальности вести параллельно две позиции графика одновременно, или работы выстраиваются в очередь — не обсуждалось, сильно влияет на итоговую длительность графика, блокирует фазу 6, шаг 3.
9. Статистика по фактически достигнутой производительности труда на завершённых объектах заказчика (для поправочного коэффициента, см. архитектурное решение 9) — не собрана, накапливать по мере появления факта. Не блокирует MVP: пока коэффициент не готов, график считается по чистой норме без поправки.

## Дорожная карта проекта (зафиксировано 2026-09-16)

Полная цепочка от сметы до графика Ганта — 6 фаз. Статус на 2026-09-16:

Фаза 1. Извлечение работ и объёма из сметы (.gsfx и Excel). ГОТОВО, проверено на 3 объектах. Остаток: сверить ГЭСН01-02-027-02 в Гранд-Смете (не блокирует).
Фаза 2. Объём трудозатрат (чел-ч, маш-ч). ГОТОВО — есть в самой смете (ресурсный метод).
Фаза 3. Определение ведущего ресурса. ГОТОВО, проверено на реальных данных. Остаток: проверить тай-брейк "максимум маш-ч" на не-земляном сборнике (не блокирует).
Фаза 4. Состав звена через сопоставление ГЭСН → ФРСН. В РАБОТЕ, шаг 1 из 4 закрыт 16.09 (см. раздел ниже).
Фаза 5. Взаимоувязка работ по технологии (ТТК). НЕ НАЧАТА. План:
  Шаг 1. Получить от заказчика инвентаризацию — для каких видов работ уже есть ТТК, в каком формате и где хранятся.
  Шаг 2. Разобрать 2-3 реальных ТТК — понять, как в них закодирована последовательность операций.
  Шаг 3. Понять, как операция ТТК соотносится со строкой сметы — по коду расценки, по названию, или нужен метод "по смыслу", как для ФРСН.
  Шаг 4. Правило связывания: для работ с ТТК — зависимости строятся автоматически; для работ без ТТК — пометка "вручную инженером ПТО", не блокирует остальной график.
  Шаг 5. Решить с заказчиком, где расставляются связи между подобъектами — до экспорта или уже в MS Project.
Фаза 6. Расчёт длительности и выгрузка в MS Project (сам график Ганта). НЕ НАЧАТА. План:
  Шаг 1 (вопрос заказчику). Какой календарь работы использовать — 5/2, 6/1, вахтовый, с праздниками или без.
  Шаг 2 (вопрос заказчику). Может ли одна бригада специальности работать параллельно на двух позициях графика одновременно, или работы этой специальности встают в очередь.
  Шаг 3 (код). Модель данных задачи графика: код, объём, чел-ч/маш-ч на единицу, ведущий ресурс, состав звена (фаза 4), зависимости (фаза 5).
  Шаг 4 (код). Формула длительности: часы ведущего ресурса / (численность звена × часов в смену × число смен), округление по строительной практике.
  Шаг 5 (код, добавлено 17.09.2026). Поправочный коэффициент на фактическую производительность: применяется поверх формулы шага 4, источник — накопленная статистика по завершённым объектам заказчика (см. открытый вопрос 9). Пока статистики нет — коэффициент = 1 (чистая норма), это временно и явно, не тихая заглушка.
  Шаг 6 (код). Сквозной прототип на одном объекте (резервуарный парк — там уже есть данные фаз 1-3), с временной заглушкой вместо состава звена.
  Шаг 7 (код). Выбор способа генерации файла MS Project (XML MSPDI или библиотека), проверка, что Project корректно открывает результат.
  Шаг 8 (проверка). Прототип графика — на сверку инженеру ПТО/прорабу по одному реальному объекту перед масштабированием.

## Действующее ТЗ: построение таблицы соответствия ГЭСН → ФРСН (Нормы труда)
Цель: для каждого из 157 уникальных кодов ГЭСН, реально встречающихся в сметах заказчика, найти соответствующую норму (или несколько норм, если позиция ГЭСН состоит из нескольких операций) в сборниках ФРСН, чтобы взять оттуда состав звена — недостающее звено для перевода чел-часов ГЭСН в календарные дни. Результат — не автоматическое сопоставление, а таблица-черновик кандидатов на ручное подтверждение заказчиком, с возможностью дополнять её по мере новых смет.

Шаг 1. ВЫПОЛНЕНО (2026-09-16) — см. "Состав звена и источник норм труда" выше.

Шаг 2. Написать парсер markdown-таблиц ФРСН (все 71 файл в docs/ФРСН) и извлечь: шифр, наименование, измеритель, НТ рабочих чел-ч, НТ машинистов чел-ч, состав звена (профессия+разряд+количество). Главная техническая сложность: шифр нормы иногда разбит PDF-экстрактором на две строки таблицы (например "Н-54-04-012-" и "50-01" переносится в ячейку следующей строки), заголовок таблицы повторяется на каждой странице исходного PDF.
